Behavior Tree(BT)를 활용한 보스 AI



Problem: 보스의 복잡한 페이즈(Phase) 변화, 스킬, 타겟팅 로직이 얽혀 스파게티 코드 가능성
Solution: 행동 트리(BT)의 Action 노드를 상속 구조로 모듈화하고, 타겟(유저) 상실 시 즉시 대응하는 예외처리(안전장치) 노드를 Decorator로 배치
Performance Gain: 보스 패턴 로직의 재사용성 확보

서버 물리 엔진(Jolt) 부하 억제 설계



Problem: 다수의 플레이어와 몬스터 객체 물리 연산을 서버가 모두 담당할 경우 심각한 물리 스레드 병목 발생
Solution: 대기 중인 NPC의 Motion Type을 Kinematic/Static(Sleep 상태)으로 설정하여 연산에서 제외하고, 교전 시 Dynamic으로 자동 승격(Dynamic Promotion)
Performance Gain: 충돌 연산 부하 최소화를 통한 안정적 서버 물리 프레임 타임 확보

정밀 피격 동기화를 위한 지연 보상 (Rewind)




Problem: 네트워크 지연(Ping)으로 인해 클라이언트 화면의 몬스터 위치와 서버 위치가 달라 타격감 훼손
Solution: 모든 물리 객체의 최근 1초간 위치/히트박스 스냅샷을 원형 큐에 저장. 공격 패킷 타임스탬프 기반 과거 시간으로 Rewind 후 판정 처리
Performance Gain: Ping 100ms 환경에서도 불일치 없는 서버 피격 판정 달성

Data Race가 없는 안전한 Room(인스턴스 던전) 아키텍처



Problem: 한 방(Room)에 속한 객체 상태를 여러 워커 스레드가 동시 다발적으로 접근하여 수정하면 데이터 오염 및 데드락 위험
Solution: 방(Room)마다 고유한 Job Queue(명령 대기열)를 부여하여, 상태를 변경하는 모든 로직(이벤트)을 큐에 밀어넣고 단일 스레드 흐름으로 순차 처리(직렬화)
Performance Gain: 객체 단위의 동기화 락(Lock) 비용 완전 제거로 인해 서버 반응 속도 향상 및 데드락 100% 방지, MO RPG특성을 이용

시야 처리 병목 최적화 (Sector Grid)



Problem: 20만 마리의 NPC와 유저가 서로의 거리를 O(N^2)로 계산하여 서버 틱 심각한 저하 발생
Solution: 공간을 고정 크기의 Grid(Sector)로 분할하고 std::shared_mutex(Read-Write Lock)를 적용하여 인접 섹터의 객체만 탐색하도록 변경
Performance Gain: 탐색 복잡도를 O(k) 수준으로 낮추어 동시 접속자 수 4400명 안정적 유지

네트워크 I/O 병목 및 데이터 프래그멘테이션 최적화



Problem: 매 틱마다 쏟아지는 수많은 객체의 이동/투사체 패킷 전송(Send) 시스템 콜 비용 과다
Solution: 전송 큐에 패킷을 버퍼링 후 WSABUF 배열을 이용한 Scatter-Gather I/O(Batching)로 뭉쳐서 보내고, 수신단에서 링 버퍼 기반 재조립(Reassembly) 파서 구현
Performance Gain: WSASend 시스템 콜 횟수 대폭 감소 및 패킷 유실률 제로 달성

DB 스레드 분리 및 Stored Procedure 설계



Problem: ODBC DB 접근(동기식) 시 IOCP 워커 스레드가 블로킹되어 서버 응답 불능(Starvation) 발생 위험
Solution: DB 전담 스레드 풀을 분리하고 Lock-Free Queue로 작업을 위임. 복잡한 쿼리는 DB의 Stored Procedure(저장 프로시저)로 호출해 통신 및 쿼리 비용 최소화
Performance Gain: 워커 스레드의 I/O 블로킹 완전 제거로 동접 5,000명 환경에서도 지연 없는 즉각적 응답 보장

Lua Script를 활용한 확장성 있는 NPC AI



Problem: 20만 객체의 모든 AI 패턴을 하드코딩하기 어렵고, 공유된 Lua State에 여러 스레드가 접근하면 심각한 락(Lock) 병목 발생
Solution: C++ 서버에서 `thread_local` 기반으로 워커 스레드마다 독립적인 `lua_State` 풀을 유지하여, 상호 배제(Lock) 비용 없이 AI 스크립트 고속 실행
Performance Gain: 하드코딩 탈피 및 동기화 오버헤드 0%를 달성하여 방대한 AI 처리량 확보

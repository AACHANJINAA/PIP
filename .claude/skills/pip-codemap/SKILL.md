# PIP 코드맵 사용법

PIP의 소스 구조는 폴더별 `CODEMAP.md`에 정리되어 있다. 코드를 찾거나 고치기 전에 해당 문서를 먼저 읽고, 구조를 바꿨으면 문서를 같이 고친다.

## 읽을 문서

| 작업 대상 | 먼저 읽을 문서 |
|---|---|
| 전체 개요, 그 밖의 폴더, 진행 중 설계 문서 | `CODEMAP.md` (저장소 루트) |
| 클라이언트 (`Client/Client`) | `Client/Client/CODEMAP.md` |
| 서버 (`Server/Server`) | `Server/Server/CODEMAP.md` |
| 패킷·공용 헤더 (`Common`) | `Common/CODEMAP.md` |
| 진행 중인 기능 | `CODEMAP.md`의 "진행 중 설계 문서" 표에 있는 `기획 & 계획/*.md` |

`GEMINI.md` 파일들은 예전에 작성된 것이라 지금 코드와 다른 부분이 있다. CODEMAP과 다르면 CODEMAP과 실제 소스를 믿는다.

## 문서와 코드가 다를 때

CODEMAP은 작성 시점의 소스를 보고 쓴 것이다. 문서 내용과 실제 소스가 다르면 소스가 맞다. 확인한 차이는 그 자리에서 CODEMAP에 반영한다.

## 갱신 규칙

다음을 바꾸면 해당 폴더의 `CODEMAP.md`를 같이 고친다.

- 파일·클래스 추가, 삭제, 이름 변경
- 클래스의 역할이나 책임이 바뀜
- 프레임·스레드 흐름, 갱신 순서가 바뀜
- 패킷 추가·변경 (`Common/CODEMAP.md` 2장, 서버 허용 목록, 클라 핸들러)
- 디버그 키, 컴파일 스위치, 빌드 설정, 작업 폴더·경로 규칙
- 알려진 문제가 생기거나 해결됨

진행 중 설계 문서의 상태가 바뀌면 루트 `CODEMAP.md`의 "진행 중 설계 문서" 표도 고친다.

작성 방식: 한국어, 파일·클래스 단위 표, 한 항목은 역할과 핵심 동작만. 코드 위치는 파일명과 함수명으로 적는다(줄 번호는 금방 틀어지므로 쓰지 않는다).

작성일: 2026-10-01
대상: 플레이어 평타 (대검 스킬은 평타 구조가 잡힌 뒤 적용)

## 1. 현황 진단

### 1.1 평타 처리 흐름 (변경 전 기준)

| 단계 | 내용 | 위치 |
|---|---|---|
| 입력 | 좌클릭 → 공격 시작, `SwordSwing` 사운드 | `Client/Client/MainPlayerScript.cpp:982` |
| 애니메이션 | 매 프레임 `play("attack", false, 1.8f)` 호출 | `MainPlayerScript.cpp:611` |
| 판정 요청 | 애니메이션 30% 시점에 `C2S_P_ACTION` 전송 | `MainPlayerScript.cpp:1351` |
| 서버 판정 | 1m 앞 반경 2m 구체, 리와인드 적용 | `Server/Server/Room.cpp:1602` |
| 서버 피격 처리 | HP 감소, `HITTED` 상태, 넉백 15, 피격 쿨다운 0.5초 | `Server/Server/NPC.cpp:203` |
| 클라 응답 처리 | HP 갱신, 데미지 텍스트, `HitSound` | `Client/Client/NetworkManager.cpp:617` |

평타로 일반 몬스터를 치면 나오는 피드백은 데미지 숫자, 타격음, 서버 넉백으로 밀리는 것뿐이었다.

### 1.2 발견한 문제

1. **히트스톱이 동작하지 않음 (죽은 코드)**
   - `SetHitStop`은 `TimerManager::instance()`(싱글톤)에 값을 썼지만, 프레임 루프는 `GameFramework`의 멤버 `_gameTimer`(별도 인스턴스)를 사용했다.
   - 싱글톤은 `Tick`도 안 돌고 아무도 읽지 않아서 효과가 없었다.
   - 설령 동작했더라도 전역 델타타임을 줄이는 방식이라 월드 전체(물리, 리플리케이션, 카메라, 사운드)가 멈추는 구조였다.
2. **일반 몬스터 피격 모션 없음**
   - `NPCScript`의 `HITTED` 분기가 주석 처리되어 피격 시 `Idle`이 재생됐다.
   - `A_DragonBrute_Hit.gltf`, `A_MagicConstruct_Combat_Unarmed_Hit.gltf` 파일은 있지만 로드하지 않았다. 피격 모션은 보스(`TainerScript`)만 재생했다.
3. **평타 카메라 셰이크 없음**: 셰이크는 스킬일 때만 걸린다.
4. **모든 피드백이 서버 응답 이후**: 서버 왕복 지연만큼 늦게 나온다. 클라이언트 무기 충돌 콜백(`WeaponScript::on_collision_enter`)은 로그만 찍는다.
5. **연타가 씹힐 수 있음**: 서버 NPC 피격 쿨다운 0.5초 안에 들어온 공격은 판정 실패로 패킷 자체가 안 온다. 여러 명이 같은 몬스터를 칠 때도 마찬가지다.
6. **애니메이션 속도 덮어쓰기**
   - `play()`가 매 프레임 호출되면서 `_animationSpeed`를 덮어쓴다(`AnimationComponent.cpp:128`).
   - 그래서 `set_anim_speed(0)` 방식의 히트스톱은 다음 프레임에 바로 풀린다. 과거에 히트스톱을 넣었다가 애니메이션이 제대로 안 나왔던 원인으로 추정한다.

### 1.3 무기와 칼 부착 구조

- **눈에 보이는 칼**: 플레이어 스킨 메쉬 `SKM_DKF_Full_With_Sword.gltf`의 `M_DKF_Sword` 프리미티브로 구워져 있다.
- **보이지 않는 무기 오브젝트**: `SocketComponent`로 `hand_r`에 붙인 `SM_Weapon_Sword__10`이다. 렌더링은 꺼져 있고, 스킬 파티클과 무기 캡슐 센서가 달려 있다(`MainPlayerScript.cpp:227`).

칼 메쉬 분석 결과(glTF 직접 파싱):

- 칼 정점 3087개 전부 `ik_hand_r` 뼈에 가중치 1.0으로 묶여 있다. 칼은 이 뼈와 같이 움직이는 강체다.
- `ik_hand_r`의 역바인드 행렬이 단위행렬이라, 메쉬 좌표가 곧 뼈 기준 좌표다.
- 뼈 기준으로 칼은 **+Z축**을 따라 z = -0.152 ~ 1.142(길이 약 1.29m)에 놓여 있다.
- 중심축에서 최대 거리는 0.132(코등이), 95%는 0.096 이내다.

현재 무기 캡슐(소켓 오브젝트에 붙은 `PhysicsColliderComponent`)의 문제:

1. **기준이 다름**: `hand_r`(다른 뼈) 기준에 손으로 맞춘 오프셋, Y축 1.9m(반지름 0.15, 반높이 0.8)다. 실제 칼보다 약 60cm 길고 축도 다르다.
2. **첫 평타 이후 손을 안 따라감**: 평타 종료 시 `set_isFollowAnimation(false)`로 바뀌고(`MainPlayerScript.cpp:649`), 다시 `true`가 되는 곳은 스킬 시작(`:1011`)뿐이다. 스킬 연출(칼을 공중에 세우기)용 토글이다.
3. **판정에 쓰이지 않음**: `set_attack_active`로 켜고 끄기만 하고, 충돌 콜백은 로그만 찍는다.

소켓 오브젝트(`MainWeapon`)는 대검 스킬 연출(파티클 목표 점 추출, 파티클 부모, 파티클 계산 기준 행렬)이 쓰고 있으므로 **그대로 둔다**. 새 칼날 캡슐은 이 오브젝트와 분리한다.

### 1.4 뼈 자세 저장 구조

- 뼈의 모델 공간 행렬(`ReadGLTFMesh::_nodes[i]._global_transform`)은 **캐시된 공용 메쉬**에 저장된다. 같은 다크나이트 메쉬를 쓰는 모든 캐릭터(내 플레이어, 다른 플레이어, `Main_Scene` 더미)가 같은 곳에 덮어쓴다.
- 소켓은 이 문제의 영향을 받지 않는다. 한 오브젝트 안에서 `AnimationComponent` → `SocketComponent` 순서로 `late_update`가 돌도록 고정되어 있어서(`GameObject.cpp:180`), 자기 자세가 쓰인 직후에 읽는다.
- 문제가 되는 건 **그 순서 밖에서 뼈를 읽을 때**다. 예를 들어 `MainPlayerScript::update`에서 읽으면 직전 프레임에 마지막으로 애니메이션된 다른 캐릭터의 자세를 읽는다.
- 캐릭터별 자세는 `AnimationComponent::_boneTransforms`에만 있다. 이 값은 GPU용 스키닝 행렬이라 `Transpose(IBM × Global)` 형태다(`ReadGLTFMesh.cpp:571`).

### 1.5 클라이언트 물리 현황

- Jolt는 이미 초기화되어 있고, 0.02초 고정 스텝으로 갱신된다(`GameFramework.cpp:722`).
- 메인 씬 NPC에는 클라이언트 히트박스가 없다. `Chess_Scene`에만 있다.
- 지형 물리 생성은 주석 처리되어 있다(`TerrainLoader.cpp:34`).
- 키네마틱 센서와 키네마틱 바디 사이의 접촉은 기본 설정으로는 보고되지 않는다(`mCollideKinematicVsNonDynamic` 미설정).
- 클라이언트 Debug 빌드에 `JPH_DEBUG_RENDERER`가 정의되어 있다.

## 2. 완료한 작업

클라이언트 Debug x64 빌드와 인게임 동작을 확인했다(2026-10-01). 커밋: `943133c03`.

### 2.1 클라이언트 시계 통일

- `GameFramework`의 `_gameTimer` 멤버를 제거하고 `TimerManager::instance()`로 통일했다(`GameFramework.cpp:429`, `:579`).
- `NetworkManager`의 `SetHitStop(0.12f, 0.05f)` 호출 두 곳을 제거했다. 시계 통일 후 이 코드가 살아나면 피격마다 월드 전체가 멈추기 때문이다.
- `TimerManager::SetHitStop`과 `_gameTimeScale`은 남아 있지만 사용하는 곳이 없다. 정리 대상이다.
- `GetTickCount64()`는 서버 리와인드 판정용 타임스탬프라 유지했다. 서버와 같은 시계를 써야 하고, 게임 시간(스케일, 클램프 적용)과 섞으면 안 된다.

### 2.2 드래곤 브루트 피격 모션

- `A_DragonBrute_Hit.gltf`를 로드하고 `Hit` 별칭으로 등록했다(`NPCScript.cpp:195`).
- 서버 상태가 `HITTED`이면 `Hit`를 재생한다(`NPCScript.cpp:47`).
- `AnimationComponent::has_animation()`을 추가했다. 피격 모션이 없는 몬스터는 기존대로 `Idle`로 간다.
- 주의: 서버 `HITTED`는 0.5초 유지된다. 피격 모션이 그보다 길면 중간에 `Idle`로 끊길 수 있다.
- 매직 컨스트럭트는 Hit 파일이 있으므로 로드 두 줄만 추가하면 적용된다.

### 2.3 1단계: 칼날 캡슐 부착과 검증 (2026-10-04 완료)

- 상세: `BoneCollider_Spec_KR.md`. 커밋: `a4c6a99bd`, `fb8e090f8`, `19054182f` 등.
- 캐릭터별 뼈 자세 보관, 뼈 부착 콜라이더(`QueryOnly`), 칼날 캡슐(`ik_hand_r`, 중심 (0, 0, -0.495), 반지름 0.1), 클라이언트 물리 기록(F8/F7).
- JoltViewer에 `-focus` 인자와 `RunViewer.py` 실행 도우미 추가.
- 남은 확인: 다인 플레이에서 내 캡슐이 내 칼에 붙어 있는지 재테스트.

### 2.4 2단계: 평타 예측 판정 (2026-10-04 동작 확인)

- 상세: `MeleeHitPrediction_Spec_KR.md`. 커밋: `776b71626`.
- 칼날 콜라이더(`Hitbox`)가 평타 5~80% 동안 직전·현재 자세 사이를 나눠 NPC 피격 히트박스(`Hurtbox`)와 겹침을 검사하고, 맞은 대상마다 `MainPlayerScript::on_trigger_enter`로 돌려준다(Unity `OnTriggerEnter`와 비슷한 방식).

- 이번 단계는 로그만 남긴다. 연출은 3단계.
- 남은 확인: 매직 컨스트럭트·보스 히트박스 위치, 빗나가는 경우, 0.5초 쿨다운, 서버 응답과의 일치율.

## 3. 설계 방향

### 3.1 연출과 서버 확정의 분리

| 구분 | 담당 | 항목 |
|---|---|---|
| 예측 (클라 즉시) | 클라이언트 칼날 캡슐 판정 | 히트스톱, 피격 모션 시작, 타격음, 스파크, 카메라 셰이크 |
| 확정 (서버 응답) | 서버 판정 | HP, 데미지 숫자, 사망, 넉백 위치 |

불일치 처리:

- **클라 적중, 서버 빗나감**: 연출만 나가고 숫자는 안 뜬다(허용).
- **서버 적중, 클라 빗나감**: 서버 응답 시점에 연출을 재생한다. 2.2의 `HITTED` 기반 피격 모션이 이 역할을 계속 맡는다.
- 서버에는 애니메이션이 없어서 칼날 위치를 알 수 없다. 그래서 칼날 기준 판정은 클라이언트가 하고, 서버는 구체(반경 2m)로 거리만 검증하는 구조가 된다. 서버 구체가 넉넉해서 대부분 서버도 적중으로 나온다.

### 3.2 히트스톱 방식

- 전역 타임스케일은 쓰지 않는다. **공격자와 피격자의 `AnimationComponent`만** 멈춘다.
- `AnimationComponent`에 재생 속도와 별개인 히트스톱 타이머를 둔다. 타이머가 남아 있으면 `late_update`에서 시간 진행만 건너뛰므로 `play()`의 속도 덮어쓰기에 영향을 받지 않는다.
- 평타 판정 구간은 애니메이션 시간 기준이라 멈추면 같이 멈춘다. 애니메이션이 잘리지 않는다.
- 시작값: 평타 약 0.05~0.06초, 대검 0.12~0.15초.
- 현재 구현(2026-10-04): `AnimationComponent::hit_stop(duration)`. 예측 적중 시 나와 맞은 NPC에 0.05초. 체감이 약하다는 피드백이 있어 넉백 버그 수정 후 수치를 다시 정한다.

**이후 구조: 오브젝트별 시간 배율로 옮긴다 (임시 구현 대체)**

- 히트스톱은 애니메이션 기능이 아니라 "그 오브젝트의 시간"을 멈추는 개념이다. 칼 잔상, 캐릭터에 붙은 파티클, 공격 중 전진 이동, 스크립트 타이머(콤보 유예 등)도 같이 멈춰야 하는데, 기능마다 `hit_stop`을 따로 두면 빠뜨리기 쉽다.
- 언리얼의 액터별 `CustomTimeDilation`처럼 `GameObject`에 시간 배율과 히트스톱 타이머를 두고, 컴포넌트 갱신 시 `deltaTime × 배율`을 넘긴다. 히트스톱 타이머는 실제 시간으로 줄인다. 호출은 `game_object()->hit_stop(시간)`.
- **예외**: 서버 기준 위치 보간(NPC, 다른 플레이어)은 멈추면 안 된다(풀린 뒤 따라잡으며 튐). `NetMotionSync_Design_KR.md` S2·S3에서 보간을 서버 시계 기준으로 바꾸면서 분리되므로, **S3 이후에** 옮긴다.
- 옮긴 뒤 `AnimationComponent::hit_stop`은 지운다.
- **옮김 (2026-10-04, 동작 확인)**: `GameObject::hit_stop(시간)`, `set_time_scale`. `update`에서 히트스톱·배율을 적용한 시간을 계산해 그 프레임 `late_update`에도 같은 값을 넘긴다. `fixed_update`(물리 고정 스텝)는 적용하지 않는다. `AnimationComponent::hit_stop` 삭제. 예측 적중 시 나와 맞은 NPC 오브젝트에 0.05초.
- 0.35초로 늘려 본 결과 "렉 걸린 것 같다"는 체감. 히트스톱 단독으로는 길게 늘려도 타격감이 아니라 끊김으로 느껴진다. 짧게(평타 0.06~0.1초) 두고 피격자 흔들림·타격음·카메라 셰이크·피격 이펙트를 같은 순간에 붙여야 한다(3단계).

### 3.3 무기 판정 형태

삼각형 메쉬 대신 **칼날 캡슐**을 쓴다.

- 얇은 메쉬는 빠른 스윙에서 스텝 사이에 적을 통과한다. 이전 자세와 현재 자세 사이를 나눠 검사해야 하는데 캡슐이 훨씬 싸고 안정적이다.
- Jolt는 메쉬끼리 충돌을 지원하지 않는다.
- 칼날의 정확한 윤곽 차이는 체감되지 않는다.

캡슐 사양(`ik_hand_r` 뼈 기준):

| 항목 | 값 |
|---|---|
| 부착 뼈 | `ik_hand_r` |
| 중심 | (0, 0, -0.495) (엔진은 glTF Z를 뒤집으므로 분석값 +0.495의 부호 반대) |
| 축 | Z (Jolt 캡슐은 Y축 기준이라 X축으로 90도 회전) |
| 전체 길이 | 약 1.29m (반높이 = 0.647 - 반지름) |
| 반지름 | 0.1 (확정, 칼날만 0.096, 코등이 포함 0.132) |

판정 방식: 접촉 콜백 대신 판정 구간(평타 진행도 5~80%) 동안 매 프레임 직접 겹침 검사를 한다. 이전 프레임과 현재 프레임의 칼 자세 사이를 회전 15도·이동 0.2m 단위(1~12단계)로 나눠 검사해서 건너뜀을 막는다(2단계에서 구현).

### 3.4 뼈 자세와 칼날 캡슐의 구조

**뼈 자세: `AnimationComponent`가 캐릭터별로 보관한다**

- `late_update`에서 애니메이션을 계산할 때, 스키닝 행렬과 함께 **조인트별 모델 공간 행렬**(`Global`)도 캐릭터별 배열에 복사해 둔다. `ReadGLTFMesh::update_animation`(벡터 버전)에 출력 인자를 하나 추가한다.
- 조회 함수 `get_bone_model_matrix(bone_name)`를 제공한다. 뼈 이름에서 조인트 인덱스로 가는 표는 메쉬별로 한 번 만들어 캐싱한다. `ik_hand_r`은 조인트 86번이다.
- 스키닝 행렬에서 역산(`Inverse(IBM) × Transpose(...)`)하는 것보다 싸고 정확하다. 조인트 89개 행렬 복사는 부담이 없다.
- 보관된 값은 그 캐릭터의 `late_update` 이후부터 다음 프레임 `late_update` 전까지 유효하다. 읽는 쪽이 컴포넌트 순서를 신경 쓸 필요가 없어진다.
- 소켓은 지금도 올바르게 동작하므로 당장 옮기지 않는다. 나중에 같은 함수를 쓰도록 통일할 수 있다.

**칼날 캡슐: 기존 `PhysicsColliderComponent`를 확장해 뼈에 붙인다**

콜라이더에는 서로 독립된 두 축이 있어서, 파생 클래스로 나누지 않고 설정으로 조합한다.

| 축 | 선택지 | 설정 방법 |
|---|---|---|
| 어디에 붙는가 | 오브젝트 트랜스폼 (기본) / 뼈 | `attach_to_bone(bone_name)` |
| 무엇을 하는가 | Jolt 바디 생성 (기본) / 바디 없이 겹침 검사 전용 | `BodyMode::Body` / `BodyMode::QueryOnly` |

사용 예:

```cpp
auto blade = player->add_component<PhysicsColliderComponent>();
blade->initialize(ShapeType::Capsule, { r, 0.647f - r, 0 },
                  { 0, 0, -0.495f },  // center: 붙은 기준(뼈) 좌표계 오프셋
                  { 90, 0, 0 },       // rotation_offset: Y축 캡슐을 Z축으로
                  /*isSensor*/ true,
                  BodyMode::QueryOnly);
blade->attach_to_bone("ik_hand_r");
```

- `attach_to_bone`을 호출하지 않으면 지금처럼 오브젝트 트랜스폼에 붙는다. `center`, `rotation_offset`은 기존 의미 그대로이고, 기준 좌표계만 뼈로 바뀐다.
- `late_update`를 추가해 **현재·이전 프레임 월드 변환**을 계산해 보관한다. 계산식은 `로컬 오프셋 × 뼈 모델 행렬(get_bone_model_matrix) × 오브젝트 월드 행렬`이다. 판정, 기록, 이후 NPC 히트박스가 모두 이 값을 읽는다.
- 컴포넌트는 `Render` → `Animation` → `Socket` 다음에 붙으므로 같은 프레임 자세를 읽는다. 순서가 바뀌어도 보관값을 읽으므로 한 프레임 늦을 뿐 다른 캐릭터 자세를 읽지는 않는다.
- `QueryOnly`는 Jolt 바디를 만들지 않는다. 키네마틱 접촉 설정, 0.02초 물리 스텝 지연, 활성화 토글 문제가 없다.
- 기존 호출부(무기 소켓 오브젝트, `Chess_Scene` NPC)는 코드 변경 없이 동작한다.

새 게임 오브젝트로 만들지 않는 이유:

- 트랜스폼 계층, 매 프레임 월드 행렬 대입, 레이어, 생성·파괴 관리가 추가로 필요하다.
- 소켓 오브젝트처럼 "따라가기 켜짐/꺼짐" 같은 상태가 끼어들 여지가 생긴다.

같이 손볼 것:

- `get_shape()`에 반환문이 없다(`const JPH::Shape* get_shape() {};`). 호출 시 정의되지 않은 동작이므로 `_shape` 반환으로 고친다.
- `PhysicsManager`는 충돌 알림 시 `get_component<PhysicsColliderComponent>()`로 첫 번째 콜라이더만 찾는다(`PhysicsManager.cpp:49`). 바디 없는 칼날 캡슐은 상관없지만, NPC 부위별 히트박스를 여러 개 붙이는 2단계에서 문제가 된다.
- Jolt 모양은 행렬 스케일을 자동 반영하지 않는다. 플레이어(스케일 1)는 괜찮지만 스케일 1.5인 NPC(매직 컨스트럭트)에 붙일 때는 스케일을 분리해 모양 크기에 반영해야 한다(2단계).
  - 2단계 결과: 서버 히트박스가 스케일 없이 미터 단위라, 클라이언트도 `set_ignore_owner_scale(true)`로 스케일을 빼고 위치·회전만 쓰도록 했다. 모양 크기도 서버 값 그대로 둔다.

### 3.5 검증 방법: Jolt 한 프레임 기록

- 서버의 `DEBUG_VIEWER` 기록 장치(`DebugRendererRecorder`로 `physics_dump.bin` 기록, `Room.cpp:771`)를 클라이언트로 옮긴다.
- 기록한 파일은 레포의 `Jolt/JoltViewer`로 확인한다. 원점에서 먼 기록은 `-focus=x,y,z` 인자로 카메라를 옮긴다(`BoneCollider_Spec_KR.md` 7.3).
- 한 프레임에 **캡슐과 실제 칼날 삼각형을 함께** 기록한다. 칼 정점 3087개에 그 순간의 `ik_hand_r` 행렬을 곱해 와이어프레임으로 그리면, 캡슐이 칼날을 감싸는지 바로 보인다.
- `DrawBodies`는 마지막 물리 스텝 때의 바디 위치를 그려서 애니메이션보다 늦을 수 있다. 캡슐도 그 순간의 뼈 행렬로 직접 그린다.

기록 내용:

| 내용 | 색 | 그리는 방법 |
|---|---|---|
| 실제 칼날 삼각형 | 흰색 와이어 | 칼 프리미티브(재질 `M_DKF_Sword`)의 CPU 정점 × `ik_hand_r` 행렬 × 월드 행렬 |
| 칼날 캡슐 | 초록 | 컴포넌트가 계산한 현재 월드 변환으로 `DrawCapsule` |
| `ik_hand_r` 뼈 축 | RGB | `DrawCoordinateSystem` |
| 기존 물리 바디 | 기본 | `DrawBodies` (소켓 캡슐 비교용) |

트리거와 시점:

- 기존 **F8**(서버 스냅샷 요청, `MainPlayerScript.cpp:787`)에 클라이언트 기록을 같이 건다. 같은 순간의 서버 파일과 비교할 수 있다.
- 파일 이름은 `client_physics_dump.bin`으로 한다.
- 기록은 모든 `late_update`가 끝난 프레임 끝에 한다. 화면에 그려진 자세와 일치시키기 위해서다.
- 평타의 30%, 45%, 60% 시점을 자동으로 연속 기록하는 옵션을 둔다. 1.8배속이라 F8 타이밍으로 원하는 순간을 잡기 어렵기 때문이다.
- `#ifdef JPH_DEBUG_RENDERER` 안에 넣어 Release 빌드에서 빠지게 한다.

## 4. 작업 계획

### 1단계: 칼 캡슐 부착과 검증 (진행 순서: 1-1 → 1-2 → 1-3 → 1-4)

구현 상세와 사용법은 `BoneCollider_Spec_KR.md`를 따른다.

**1-1. 캐릭터별 뼈 자세 보관 (3.4)**

- `ReadGLTFMesh::update_animation`(벡터 버전)에 조인트별 모델 공간 행렬 출력 인자를 추가한다.
- `AnimationComponent`에 보관 배열과 `get_bone_model_matrix(bone_name)`를 추가한다.

**1-2. 콜라이더 확장과 칼날 캡슐 (3.3, 3.4)**

- `PhysicsColliderComponent`에 `attach_to_bone()`, `BodyMode::QueryOnly`, `late_update`(현재·이전 월드 변환 보관)를 추가한다.
- `get_shape()` 반환문 누락을 고친다.
- 플레이어에 칼날 캡슐 콜라이더를 붙인다. `ik_hand_r`, 중심 (0, 0, -0.495), X축 90도, 반지름 0.1, `QueryOnly`.
- 소켓 오브젝트와 그 충돌체는 건드리지 않는다.

**1-3. 클라이언트 한 프레임 기록 (3.5)**

- F8에 클라이언트 기록을 연결하고, 칼날 삼각형, 캡슐, 뼈 축, 기존 바디를 기록한다.
- 평타 30%, 45%, 60% 자동 연속 기록 옵션을 넣는다. → 2단계에서 판정 구간(5~80%) 매 프레임 기록으로 바꿨다.

**1-4. JoltViewer 확인**

- 대기, 평타 시작, 판정 구간, 종료 자세에서 캡슐이 칼날을 감싸는지 확인한다.
- 칼끝이 캡슐 밖으로 나오지 않는지, 뼈 축 +Z가 칼끝 방향인지 확인한다.
- 여기서 캡슐 반지름을 확정한다. → 0.1로 확정 (2026-10-04).

**1단계 검증이 끝난 뒤에 2단계로 넘어간다.**

### 2단계: 평타 예측 판정

구현 상세와 검증 결과는 `MeleeHitPrediction_Spec_KR.md`를 따른다. 1~5 모두 구현했고 드래곤 브루트로 동작을 확인했다(2.4).

1. 메인 씬 NPC에 히트박스를 추가한다. 모양과 크기는 서버 `HitboxComponent` 값과 맞춘다. 칼날 캡슐처럼 Jolt 바디 없이 모양과 변환만 들고 있는 방식을 우선 검토한다.
2. 판정 구간(5~80%) 동안 칼 캡슐 겹침 검사(`CollideShape`)를 하고, 이전·현재 프레임 변환 사이를 회전 15도·이동 0.2m 단위로 보간해 검사한다.
3. 한 번의 공격에서 같은 대상은 한 번만 맞게 한다.
4. 1-3의 기록에 NPC 히트박스와 적중 지점을 추가해 판정도 같은 방식으로 검증한다.
5. 서버 피격 쿨다운(0.5초)을 클라이언트에서도 흉내 내서 불일치를 줄인다.

### 3단계: 연출 분리

1. `AnimationComponent`에 히트스톱 타이머를 추가한다(3.2).
2. 예측 적중 시 공격자와 피격자 히트스톱, 타격음, 약한 카메라 셰이크(`add_trauma(0.15f)` 정도)를 재생한다.
3. `NPCScript`에 "로컬 피격 모션 재생 중" 타이머를 둔다. 그동안은 스냅샷 상태(`IDLE`/`MOVE`)가 애니메이션을 덮어쓰지 않게 한다.
4. 서버 응답 처리는 HP, 데미지 숫자, 사망만 담당한다. 예측이 빗나간 적중만 응답 시점에 연출을 재생한다.
5. 매직 컨스트럭트 피격 모션을 추가한다.

**진행 (2026-10-04, 타격음·카메라 킥 동작 확인)**

- 예측 적중 순간에 칼 타격음(`SwordHit` = `SwordSwingStrong.mp3`, 타격 지점 3D), 맞은 쪽 피격음(`NPCScript::on_predicted_hit`: 보스 `BossDamage`, 매직 컨스트럭트 `MagicGuardDamage`, 일반 NPC는 없음), 카메라 킥 `FreeCameraScript::add_kick(칼 진행 방향, 0.06m, 0.8도)`: 칼이 지나가는 방향을 화면에 투영한 쪽으로 위치·시선이 0.08초에 걸쳐 밀리고 0.35초에 걸쳐 돌아온다(둘 다 smoothstep. 처음 0.03초에 튀는 모양은 너무 빨랐음). 무작위로 떠는 `add_trauma`는 땅 흔들림처럼 느껴져서 쓰지 않는다(0.15는 폭이 1cm라 보이지도 않았음).
- 서버 응답(`set_hp`, `HANDLE_S2C_NPC_ATTACK`)은 1초 안에 내가 예측 적중한 NPC면 소리를 다시 내지 않는다. 예측이 빗나간 적중과 다른 플레이어의 적중만 응답 시점에 소리를 낸다.
- 기존 서버 응답 타격음 `"HitSound"`는 로드된 적이 없어 소리가 나지 않았다. NPC 피격 쪽은 `SwordHit`로 바꿨다. 플레이어 피격 쪽(`HANDLE_S2C_PLAYER_ATTACK`)은 아직 그대로다.
- 다음: 부위 피격 리액션(맞은 부위 뼈를 타격 방향으로 꺾고 스프링으로 복귀, `HitReactionComponent`). 히트스톱 동안 꺾인 자세로 멈춰 있다가 풀리며 돌아오므로 피격자 흔들림 역할을 한다.

### 4단계: 확장 (별도 계획 필요)

- 대검 스킬에 같은 구조를 적용한다. 스킬은 칼 오브젝트가 손을 떠나는 연출이 있어서 판정 기준을 따로 정해야 한다.
- 이동 예측을 서버와 맞춘다. 캐릭터 컨트롤러, 지형 충돌, 고정 스텝 길이, 컨트롤러 파라미터를 서버와 일치시키는 작업이다. 타격감과는 독립적이라 위 단계들을 막지 않는다.

## 5. 미확인 사항과 알려진 문제

1단계(1-1 ~ 1-3) 구현 이후의 알려진 문제는 `BoneCollider_Spec_KR.md` 7장에 정리했다.

- 칼날 캡슐 방향이 반대였다. 엔진이 glTF의 Z축을 뒤집어 읽으므로 중심을 (0, 0, -0.495)로 고쳤고, 기록으로 캡슐이 칼날을 감싸는 것을 확인했다.
- 기록이 세계 좌표 그대로라 뷰어에서 찾기 어려웠다. 뷰어에 `-focus=x,y,z` 인자를 추가해 해결했다.
- Release용 Jolt lib(LTCG 없이 27.5MB) 커밋으로 저장소 용량이 커진다.

- 평타 애니메이션 한 번의 실제 길이(1.8배속 기준). 서버 피격 쿨다운 0.5초와 비교해서 연타가 씹히는지 확인해야 한다.

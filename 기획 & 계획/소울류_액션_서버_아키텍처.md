# 소울류 액션 게임 서버 아키텍처 설계

## 목표
- **소울류 손맛**: 정교한 타격감과 반응성
- **정교한 충돌**: 정밀한 hitbox/hurtbox 시스템
- **프로그래밍 최소화**: 물리엔진 활용으로 코드 복잡도 감소
- **네트워크 최적화**: 액션의 즉각성과 서버 성능 양립

## 핵심 아키텍처 설계

### 1. 하이브리드 Physics Authority 시스템

#### A) 계층적 물리 처리
```cpp
enum class PhysicsAuthority {
    CLIENT_PREDICTED,    // 플레이어 움직임 - 클라이언트 예측
    SERVER_AUTHORITATIVE, // 공격/피해 - 서버 권한
    SHARED_SIMULATION    // 환경 물리 - 공유 시뮬레이션
};

class ActionPhysicsManager {
private:
    JPH::PhysicsSystem* combatPhysics;    // 전투 전용 고정밀 physics
    JPH::PhysicsSystem* movementPhysics;  // 이동 전용 최적화 physics
    
public:
    void UpdateCombatFrame(float deltaTime) {
        // 전투는 120Hz 고정밀 시뮬레이션
        combatPhysics->Update(deltaTime, 2);
        
        // 이동은 60Hz 일반 시뮬레이션  
        movementPhysics->Update(deltaTime, 1);
    }
};
```

### 2. 소울류 전투 시스템 구조

#### A) Frame-Perfect Combat Physics
```cpp
class SoulslikeCombatSystem {
    struct AttackFrame {
        uint32_t frameStart;
        uint32_t frameEnd;
        JPH::Shape* hitboxShape;
        DamageInfo damage;
        bool isActive;
    };
    
    struct DefenseFrame {
        uint32_t iframeStart;    // 무적 프레임
        uint32_t iframeEnd;
        bool isBlocking;
        Vec3 blockDirection;
    };
    
public:
    void ProcessCombatFrame(uint32_t frameNumber) {
        // 1. 활성 공격 hitbox 업데이트
        UpdateActiveHitboxes(frameNumber);
        
        // 2. Jolt collision detection으로 정밀 충돌 계산
        ProcessHitDetection();
        
        // 3. 무적/블록 프레임 검증
        ValidateDefenseFrames(frameNumber);
        
        // 4. 즉시 피드백 전송
        SendCombatFeedback();
    }
};
```

#### B) 정교한 Hitbox/Hurtbox 시스템
```cpp
class PrecisionHitboxSystem {
    struct CombatCollider {
        JPH::BodyID bodyID;
        ColliderType type;        // HITBOX, HURTBOX, WEAPON
        FrameWindow activeFrames;
        DamageProfile damage;
    };
    
public:
    void CreateWeaponHitbox(const AttackData& attack) {
        // Jolt의 정밀한 convex shape으로 무기 hitbox 생성
        JPH::ConvexHullShapeSettings hitboxShape;
        hitboxShape.mPoints = attack.weaponTrajectory;
        
        // 정확한 시간 동기화로 hitbox 활성화
        ActivateHitboxAtFrame(attack.startFrame);
    }
    
    CollisionResult CheckPreciseHit(const CombatCollider& hitbox, 
                                   const CombatCollider& hurtbox) {
        // Jolt의 narrow phase로 정밀 충돌 계산
        JPH::CollideShapeSettings settings;
        settings.mMaxSeparationDistance = 0.01f; // 1cm 정밀도
        
        return physicsSystem->CollideShapes(
            hitbox.shape, hitbox.transform,
            hurtbox.shape, hurtbox.transform, 
            settings
        );
    }
};
```

### 3. 네트워크 예측 및 롤백 시스템

#### A) Client-Side Prediction with Server Reconciliation
```cpp
class PredictiveActionSystem {
    struct GameFrame {
        uint32_t frameNumber;
        PlayerInput input;
        PhysicsState worldState;
        std::vector<CombatEvent> events;
    };
    
    RingBuffer<GameFrame, 60> frameHistory; // 1초분 히스토리
    
public:
    void ClientUpdate(const PlayerInput& input) {
        // 1. 클라이언트 예측 실행
        GameFrame predictedFrame = PredictFrame(input);
        
        // 2. 즉시 시각적 피드백
        ApplyVisualEffects(predictedFrame);
        
        // 3. 서버에 input 전송
        SendInputToServer(input, predictedFrame.frameNumber);
    }
    
    void ServerReconciliation(const ServerFrame& authoritative) {
        // 서버 결과와 차이가 있으면 롤백 후 재시뮬레이션
        if(HasMisprediction(authoritative)) {
            RollbackToFrame(authoritative.frameNumber);
            ResimulateFromFrame(authoritative);
        }
    }
};
```

#### B) 서버 지연 보상 (Lag Compensation)
```cpp
class LagCompensationSystem {
public:
    bool ValidateHit(const AttackEvent& attack, uint32_t clientTimestamp) {
        // 클라이언트 지연시간 계산
        float latency = CalculatePlayerLatency(attack.playerID);
        
        // 과거 시점으로 되돌려서 충돌 검증
        uint32_t compensatedFrame = clientTimestamp - LatencyToFrames(latency);
        
        // 해당 시점의 world state 복원
        PhysicsState historicalState = GetHistoricalState(compensatedFrame);
        
        // 복원된 상태에서 충돌 재계산
        return ValidateHitAtFrame(attack, historicalState);
    }
};
```

### 5. 성능 최적화 전략

#### A) Spatial Partitioning for Combat
```cpp
class CombatSpatialManager {
private:
    struct CombatZone {
        AABox bounds;
        std::vector<PlayerID> activePlayers;
        JPH::PhysicsSystem* localPhysics; // 구역별 독립 physics
    };
    
    std::vector<CombatZone> combatZones;
    
public:
    void UpdateCombatZones(float deltaTime) {
        // 활성 전투 지역만 고해상도 physics 실행
        for(auto& zone : combatZones) {
            if(zone.activePlayers.size() > 0) {
                zone.localPhysics->Update(deltaTime, 2); // 120Hz
            }
        }
    }
};
```

#### B) Event-Driven Combat Updates
```cpp
class EventDrivenCombat {
public:
    void OnAttackStart(const AttackEvent& event) {
        // 공격 시작 시에만 해당 지역 physics 활성화
        ActivateCombatPhysics(event.attackerPosition, event.attackRange);
        
        // Jolt collision callback 등록
        RegisterCollisionCallback(event.hitboxID, 
            [this](const CollisionEvent& collision) {
                ProcessHitEvent(collision);
            });
    }
    
    void OnAttackEnd(const AttackEvent& event) {
        // 공격 종료 시 physics 비활성화
        DeactivateCombatPhysics(event.attackerPosition);
    }
};
```

### 6. 구현 우선순위

#### Phase 1: 기본 전투 Physics (2주)
1. 이중 Physics 시스템 구축 (combat + movement)
2. 기본 hitbox/hurtbox 시스템
3. Frame-based 충돌 검증

#### Phase 2: 네트워크 최적화 (2주)  
1. Client prediction 구현
2. Server reconciliation
3. Lag compensation

#### Phase 3: Data-Driven 시스템 (1주)
1. JSON 기반 전투 데이터 로더
2. 자동 physics setup
3. 실시간 데이터 수정 지원

## 기술적 장점

### 🎯 소울류 손맛 구현
- **Frame-perfect timing**: 정확한 프레임 기반 전투
- **정밀한 충돌**: Jolt의 고정밀 collision detection
- **즉각적 피드백**: Client prediction으로 지연 없는 반응

### ⚡ 성능 최적화
- **구역별 Physics**: 전투 지역만 고해상도 시뮬레이션
- **Event-driven**: 필요할 때만 physics 활성화
- **계층적 처리**: 중요도에 따른 차등 처리

### 🛠️ 개발 편의성
- **Data-driven**: JSON으로 전투 로직 정의
- **자동 Setup**: Physics 설정 자동화
- **Hot-reload**: 런타임 데이터 수정 가능

이 아키텍처로 소울류 특유의 정교한 타격감과 손맛을 네트워크 환경에서도 구현할 수 있습니다.

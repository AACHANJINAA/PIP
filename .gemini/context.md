개발 철학: 

* 이 게임 프로젝트 4학년 졸업 작품용이다.
* 클라이언트나 코드나 상용 게임의 좋은 점들과 디자인 패턴을 베끼면서 연구과제 3개와 재밌는 게임을 만드는게 목표다.
* 따라서 C++과 WinApi, DX12등의 API로만 구현하는 것이 목표이다.
* 연구과제는 

1. &nbsp;glTF 파서 = 언리얼이나 다른 상용 모델링 툴에서 만든 glTF 메쉬와 씬들을 직접 json과 바이너리를 읽어서 우리게임에서 mesh 클래스의 형태로 사용하기 위함 Assimp안 쓰고 직접 로드하기 위함 -> 3D 모델에 대한 이해 증가를 위함
2. PBR 렌더 파이프 라인 = 원래 조명계산 칼라+노멀 => 거칠기, 스펙큘러등을 사용해서 좀더 현실적인 그래픽사용
   + IBL 이미지 기반 라이팅으로 스카이박스를 따라서 이미지 색상이 거칠기가  일종의 별빛처럼 작용해서 현실적인 그래픽과 현실적 텍스쳐 구현
3. Jolt 오픈 소스 물리엔진 라이브러리 서버 연동 = 서버에서 물리 충돌과 물리 체크 판정을 하여 현실적인 물리 시뮬레이션을 가능하게 하고 해킹의 위험으로 부터 원천차단하며 무거운 물리 엔진 업데이트를 돌리는 것이 아니라 kinematic body들을 직접 움직이게 하여 서버에서 무거운 물리 엔진을 돌릴 수 있다는 것을 기술적으로 보여주기 위함



이 게임 기획 철학:

* 엘든링과 다크소울과 같은 다크 판타지 장르를 만들고 싶음
* 보스전과 잡몹전투 등 전투를 구현하고 싶음
* 4명 멀티 플레이 엘든링 컨셉의 게임을 만들고 싶음
* 무기에 따라서 스킬이 바뀌는 기억의 공명 핵심 전투 시스템을 구현하고 싶음
* 무기가 재료 아이템에 따라 강화되는 강화 시스템과 보스전을 통해서 점점 강해지는 것을 유저에게 체험 시켜주고 싶음
* "점점 적이 강해진다면 너는 옳은길을 가고 있는거야"라는 이야기를 느끼게 해주고 싶다.
* 점점 강해지는 필드와 스테이지를 돌파해 나아가는 것이 목표임

서버 설계 철학:

* IOCP를 사용하여 수많은 플레이어를 받는 것이 목표
* 안전한 세션의 삭제와 추가를 가능하게 하여 오랫동안 무리 없이 서버를 켜놓는것이 목표
* 
* 서버는 최대한 많은 플레이어가 들어가도 아무런 문제없이 돌아가는 것이 목표
* mo 게임이므로 방 기준에서는 로직스레드 하나에서 돌아가는 싱글 스레드 코드로 코딩해서 락킹 오버헤드나 논블락킹 오버헤드 삭제해서 서버가 뻑가는 일 없도록 하는게 목표
* 서버의 설계 원칙은 유지 보수성이 뛰어난 OOP로 OOP 원칙과 디자인 패턴을 다양하고 효율적으로 적용하되, 필요한 곳에서는 최적화를 통해서 서버의 속도를 유지해야함
* 서버는 서버만의 코딩 컨벤션을 따름
* 실제 상용 게임엔진인 unreal과 unity의 좋은 것들을 가져온다 예를 들어 BehaviorTree와 Component 패턴을 적용하여 개발이 쉽고 빠르게 진행되면서 코드 품질을 계속 유지한다.
* 물리엔진의 무거운 점을 이해하고 있기 때문에 거의 모든 객체들을 Dynamic 레이어가 아닌 Npc나 static 레이어 등으로 만들어서 실제 움직임은 내가 직접 조종하고 이동가능 체크는 shape 캐스트를 사용해야함 그래야 물리 업데이트의 무거운 업데이트를 피할 수 있음



클라이언트 설계 철학

* unity의 프로그래머에게 좋은 설계철학을 베낄수 있으면 베껴서 그대로 사용하여서 프로그래머들이 프로그래밍 하기 편하게 프로젝트 구성하고 유지보수가 쉽게 코드를 짜는 것이 1차 목표
* 클라이언트에서 여러 컨텐츠와 비주얼 적으로 멋있어 보이는 효과를 구현 할 수 있게 끔 지원하는게 2차 목표
* 클라이언트에서는 최대한 높은 프레임이 나오면서 좋은 렌더링 효과를 뽑을 수 있어야함
* 많은 오브젝트와 많은 광원이 있어도 대처가 가능하도록 렌더링 패스를 구성해야함
* 언리얼에서 파싱한 glTF 데이터를 읽고 사용하는 것이 제일 중요함 레벨 에디터를 언리얼로 사용 할것이기 때문이다.

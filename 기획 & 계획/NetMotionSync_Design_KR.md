# NPC·다른 플레이어 이동 및 넉백 동기화 설계

작성일: 2026-10-04
관련 문서: `HitFeel_Plan_KR.md` 3단계(연출), `MeleeHitPrediction_Spec_KR.md` (예측 적중)

---

## 1. 목표

- 서버가 움직이는 대상(NPC, 보스, 다른 플레이어)이 클라이언트에서 **매끄럽고, 모션과 이동이 어긋나지 않게** 보이게 한다.
- 넉백, 돌진처럼 크게 움직이는 동작을 서버와 클라이언트가 **같은 정의로 계산**해서, 타격 연출(히트스톱 등)과 이동이 맞물리게 한다.
- 서버 권한 구조(위치·판정은 서버가 확정)는 그대로 유지한다.

범위 밖: 내 플레이어의 예측·보정 방식 변경, 결정론적 시뮬레이션/되감기(롤백) 구조, 서버 판정 방식 변경.

---

## 2. 업계 사례 (조사 요약)

| 사례 | 방식 | PIP에 주는 시사점 |
|---|---|---|
| 몬스터 헌터 월드 | 히트스톱은 각자 클라이언트에서만 도는 연출. 동료 화면에서는 내 공격의 히트스톱이 보이지 않음 | 히트스톱은 서버가 몰라도 된다. 공격자 화면 연출로 충분 |
| 엘든 링 | 맞았는지는 정하는 쪽 화면 기준, 반응은 이벤트로 받아 재생 (지연이 크면 반응이 늦게 보임) | 반응·이동은 위치 샘플이 아니라 이벤트로 다룬다 |
| 언리얼 Root Motion Source | 넉백 같은 강제 이동을 "방향·세기·곡선·지속 시간·시작 시각" 정의로 복제. 서버·클라이언트가 같은 함수로 계산하고 보정은 작은 오차만 처리 | 넉백·돌진을 이동 정의(모션 이벤트)로 동기화한다 |
| Source 엔진 계열 | 서버 시각이 찍힌 스냅샷을 버퍼에 쌓고, 약간 과거 시점을 두 스냅샷 사이에서 보간 | 평상시 이동은 시각 기준 보간 버퍼로 |
| 포 아너 | 결정론적 시뮬레이션 + 되감기 | 구조 전체를 바꿔야 해서 PIP에는 맞지 않음 |

## 3. 현재 구조

### 3.1 시간

| 항목 | 현재 |
|---|---|
| 클라이언트 시계 | 각 PC의 `GetTickCount64`(부팅 후 경과, 해상도 약 16ms). 서버 시계와 기준이 다름 |
| 서버 판정 시점 | 공격 패킷의 클라이언트 시각과 서버 시각 차이의 **관측 최솟값**을 기준선으로 보고, 그보다 늦게 온 만큼 되감음 (`Player::ComputeRewindTimestamp`) |
| NPC 데이터의 서버 시각 | `NPCMoveData._time_stamp`에 담겨 오지만 클라이언트가 **읽지 않음** |
| 다른 플레이어 데이터의 서버 시각 | `SC_PACKET_MOVE`에 **없음** (클라이언트 틱 에코만 있음) |
| 왕복 지연(RTT) | 서버가 `SC_PACKET_MOVE._client_tick`으로 되돌려 주지만 클라이언트가 **쓰지 않음** |

클라이언트는 서버 시간 추정값도 RTT도 없다.

### 3.2 NPC·보스

| 항목 | 현재 |
|---|---|
| 서버 | 물리 60Hz 고정 스텝, 행동 트리와 이동은 서버에서만 |
| 전송 | 0.05초(20Hz)마다, 바뀐 NPC만(상태·액션·잡기·위치 변화), 셀 단위 AOI |
| 내용 | 위치, 속도, 회전, 상태, 액션 번호, 잡기 정보, HP, 서버 시각 |
| 클라이언트 위치 | 패킷 **도착 시각**부터 `위치 + 속도 × 경과`로 추측(최대 0.3초·5m), 그 목표로 초당 10~15 비율로 따라감, 10m 이상이면 순간이동 (`NPCScript::update`) |
| 클라이언트 모션 | 상태·액션 번호가 바뀐 패킷이 **도착한 순간** 모션 변경 |

### 3.3 다른 플레이어

| 항목 | 현재 |
|---|---|
| 내 클라이언트 → 서버 | 0.02초마다 위치, 이동 입력 방향, 회전, 상태, 액션 (`CS_PACKET_MOVE`) |
| 서버 → 다른 클라이언트 | 서버 로직 갱신마다, 바뀐 플레이어만 `SC_PACKET_MOVE` 브로드캐스트 (전송 간격이 서버 루프 속도에 따라 들쭉날쭉) |
| 내용 | 위치, 속도(정지·액션 중이면 0), 회전, 상태, 액션, 잡기, HP, MP, 클라이언트 틱 에코 |
| 클라이언트 위치 | 논리 위치 = 받은 위치, 매 프레임 `+ 속도 × dt`로 추측, 받은 순간의 화면 위치 차이를 오프셋으로 두고 줄여 나감, 5m 이상이면 순간이동 (`OtherPlayerScript`) |

### 3.4 넉백·큰 동작

- 넉백: 맞으면 서버가 `NPCControllerComponent::AddKnockback`으로 속도(현재 항상 초속 15m)를 주고 마찰(35)로 감속. 벽 앞에서 멈추도록 시작할 때 스윕해서 초기 속도를 줄인다. 평타 한 대에 약 3.2m, 0.43초 밀림.
  - **버그**: 공격 설정의 넉백 값(평타 5, 대검 30)이 `NPC::ValidateHit`에 전달되지 않고 15로 고정되어 있다.
- 보스 돌진(`Charge`), 잡기 돌진(`GrabCharge`) 등: 서버 행동 트리가 속도로 움직이고, 클라이언트는 20Hz 위치·속도 샘플로만 받는다.

## 4. 문제

1. **큰 동작의 시작과 끝이 어긋남**: 넉백·돌진의 정의가 오지 않고 샘플만 오므로, 클라이언트 추측이 멈출 때 더 가다 되돌아오고(오버슈트) 출발할 때 늦게 따라간다.
2. **모션과 이동의 어긋남**: 모션은 상태 패킷이 도착한 순간, 위치는 따로 보간되어 서로 다른 시점에 반영된다.
3. **네트워크 흔들림이 그대로 보임**: 도착 시각 기준이라 지연이 흔들리면 이동도 흔들린다. 다른 플레이어는 서버 전송 간격 자체도 일정하지 않다.
4. **타격 연출과 넉백이 따로 놂**: 클라이언트는 예측 적중 순간을 알지만, 넉백은 서버 위치가 도착해야 시작되고 그 모양(멈춤, 감속)도 모른다.

## 5. 설계

### 5.1 시계 동기화 (ServerClock)

- 새 패킷: `CS_P_TIME_SYNC { client_time }` → `SC_P_TIME_SYNC { client_time(에코), server_time }`.
- 클라이언트: 응답을 받을 때 `RTT = now - client_time`, `offset = server_time + RTT / 2 - now`.
  - 최근 N개(예: 16) 표본 중 **RTT가 가장 작은 표본의 offset**을 쓴다(지연이 튄 표본은 시계 차이 추정이 부정확하므로).
  - offset을 바꿀 때는 한 번에 뛰지 않게 천천히 따라간다(초당 몇 ms 이내).
- 주기: 접속 직후 0.1초 간격으로 5회, 이후 2초마다.
- `ServerClock::now()`: 추정 서버 시각(ms, double). 클라이언트 쪽 시간원은 `GetTickCount64` 대신 고해상도 시계(`QueryPerformanceCounter` 또는 `steady_clock`)로 한다.
- 서버 쪽 시각도 고해상도 단조 시계(ms)로 통일한다. `GetTickCount64`(해상도 약 16ms)는 보간 기준으로 거칠다. 리와인드 판정의 기존 타임스탬프와 같은 시계를 쓰도록 맞춘다.
- 디버그: ImGui에 RTT, offset, 표본 수를 표시한다.

**S1 구현 (2026-10-04 완료)**: 같은 PC에서 RTT 최소 0.1ms, offset −0.8ms(정수 ms 전송 시, 소수점 전송으로 수정), 흔들림 100ms에서도 offset 안정. 서버 리와인드 판정 정상.

| 위치 | 내용 |
|---|---|
| `Common/NetClock.h` | `common::NetNowMs()`(uint64 ms), `NetNowMsPrecise()`(double ms). `steady_clock` 기반 |
| `Common/Packet.h` | `C2S_P_TIME_SYNC`(1101) `{ double _client_time }`, `S2C_P_TIME_SYNC`(1102) `{ double _client_time, double _server_time }` (서버 시각을 정수 ms로 보내면 평균 0.5ms 치우쳐서 소수점까지 보냄) |
| 서버 | `GetTickCount64` 7곳(리와인드 기록·판정, NPC 시각 등)을 `NetNowMs`로 교체. `Handle_C2S_TIME_SYNC`는 네트워크 스레드에서 바로 응답. 로비·인게임 모두 허용 |
| 클라 `ServerClock` | 최근 16개 표본 중 RTT 최소 표본의 offset을 목표로, 초당 5ms 이내로 따라감(50ms 이상 차이는 즉시). 로그인 직후 0.1초 간격 5회, 이후 2초마다. 로그인 성공 시 초기화 |
| 클라 `NetworkManager` | 수신 시각을 네트워크 스레드에서 기록(메인 스레드 처리 지연이 RTT에 섞이지 않게). 인공 수신 지연·흔들림(순서 유지). 행동·이동 패킷의 클라 시각도 `NetNowMs`로 |
| 디버그 창 (F6) | RTT(최소/최근), offset(현재/목표), 추정 서버 시각, 인공 수신 지연·흔들림 슬라이더. 2026-10-06 디버그 패널(`\` 키, `DebugPanel`)의 Network 항목으로 옮김 |

- 인공 지연은 **수신 쪽만** 늦춘다. RTT는 그만큼 늘고, 왕복이 비대칭이 되어 offset 추정이 지연값의 절반만큼 치우친다. 실제 비대칭 경로와 같은 성질이라 보간 검증용으로는 충분하다.

### 5.2 스냅샷 보간 버퍼 (평상시 이동)

- 엔티티마다 최근 스냅샷 링 버퍼(서버 시각, 위치, 속도, 회전, 상태, 액션).
- **렌더 시각 = 추정 서버 시각 − 편도 지연(RTT/2) − 보간 지연** (`ServerClock::arrival_now_ms() - 보간 지연`). 보간 지연은 대상별로 둔다(확정 2026-10-04).
  - 편도 지연을 빼는 이유: 서버가 시각 T에 보낸 스냅샷은 T + 편도 지연에 도착한다. 실제 서버 시각만 기준으로 하면 보간 지연이 "네트워크 지연 + 전송 간격"을 다 덮어야 해서, 70ms·전송 간격 50ms로는 편도 지연이 20ms만 넘어도 외삽으로 빠진다. 도착 기준으로 잡으면 보간 지연은 전송 간격과 흔들림만 담당한다(Source 엔진 계열과 같은 방식).
  - 다른 플레이어: **30ms**. 클라이언트가 0.02초마다 보내고 서버가 약 16ms 루프마다 전달하므로 20~30ms 간격으로 들어온다.
  - NPC: **70ms**. 서버 전송 간격 50ms + 흔들림 여유. 보간 지연이 전송 간격보다 짧으면 다음 스냅샷이 없어 외삽이 되므로 전송 간격보다 커야 한다.
  - 값은 상수로 두고 S6에서 조정한다.
- 렌더 시각을 감싸는 두 스냅샷 사이를 보간한다. 위치는 속도를 이용한 3차 에르미트 보간, 회전은 slerp.
- 버퍼가 비면(패킷 지연) 마지막 스냅샷에서 속도로 최대 100ms만 외삽하고 멈춘다. 다음 스냅샷이 오면 보간으로 복귀.
- 상태·액션 변화도 **그 스냅샷의 서버 시각에** 적용한다. 모션 전환과 위치가 같은 시점에 맞는다.
- 위치 차이가 크면(예: 5m 이상) 순간이동으로 본다(텔레포트, 리스폰).
- NPC는 바뀔 때만 전송되므로, 오래 정지한 NPC는 마지막 스냅샷을 유지한다.
- 다른 플레이어
  - `SC_PACKET_MOVE`에 `_server_time`을 추가한다.
  - 전송 간격은 지금처럼 둔다(바뀔 때마다 서버 루프에서 전달). 서버 시각이 찍혀 있으면 간격이 일정하지 않아도 보간은 정확하다.
  - 내 플레이어는 지금 방식(예측 + 서버 보정) 유지.
- 공통 구현: `SnapshotBuffer`(보간·외삽) 클래스를 만들어 `NPCScript`, `OtherPlayerScript`가 함께 쓴다. 기존 추측 항법·오프셋 코드는 대체한다.

**S2 구현 (2026-10-04, 빌드 완료·실행 확인 전)**

| 위치 | 내용 |
|---|---|
| `SnapshotBuffer.h/.cpp` (신규) | 표본(서버 시각, 위치, 속도, 회전) 버퍼. 두 표본 사이는 속도를 쓴 3차 에르미트 + 회전 slerp. 간격이 100ms보다 길면(멈춰 있다 움직인 NPC) 앞 표본에 머물다 마지막 100ms만 보간. 최신 이후 최대 100ms 외삽. 5m 이상 차이는 순간이동. 1초 지난 표본 정리 |

**S3 구현 (2026-10-04, 클라이언트 2개로 동작 확인)**

| 위치 | 내용 |
|---|---|
| `SC_PACKET_MOVE` | 끝에 `double _server_time` 추가. 서버 `Player::CreateMovePacket`에서 `NetNowMsPrecise()`로 기록(32비트 시각이 아니라 복원 불필요) |
| `OtherPlayerScript` | 기존 추측 항법(`_logicalPosition += 속도 × dt`)과 오프셋 감소(`_visualOffset`), `on_sync_*` 함수들을 삭제. `on_server_move`가 위치·회전을 버퍼에, 상태·액션·잡기·HP·MP를 대기열에 쌓고, `update`에서 렌더 시각(`arrival_now_ms − 30ms`)에 닿은 상태를 먼저 적용한 뒤 위치·회전을 보간. 공격음은 상태 적용 시점에 재생. 잡기 중 보스 손 뼈 부착은 그대로(보간보다 우선) |
| 생성·부활 | `reset_transform(위치, 서버 회전)`: 버퍼·대기열을 비우고 **현재 렌더 시각**에 표본 하나를 넣음. 추정 서버 시각에 넣으면 그보다 이른 서버 시각을 가진 뒤이은 이동 패킷이 버려지므로(약 RTT/2 동안) 렌더 시각을 쓴다. 같은 이유로 NPC 생성(`initialize_from_server`)도 렌더 시각으로 바꿈 |
| F6 창 | 보간 상태 집계를 NPC·플레이어로 나눠 표시. 유령(서버 최신 위치) 상자를 다른 플레이어에도 표시 |

- 서버는 바뀔 때만(`IsDirty`) 보내므로 멈춘 플레이어는 Capped로 세는 것이 정상이다(정지 시 속도 0이라 위치는 그대로).
- 오래 멈췄다 움직이면 첫 구간은 버퍼 규칙대로 마지막 100ms만 보간한다. 첫 이동 표본 하나 분량(약 20ms 이동)이라 눈에 띄지 않는다.

### 5.3 모션 이벤트 (넉백·돌진 등 큰 동작)

정해진 궤적으로 움직이는 동작은 위치 샘플 대신 **정의**를 보낸다.

```
MotionEvent
  entity_id
  motion_id        : 이벤트 고유 번호 (취소·종료 짝 맞추기)
  type             : Knockback / Charge / Leap ...
  start_time       : 서버 시각
  start_pos, end_pos : 서버가 시작할 때 벽·지형 스윕으로 확정한 시작·끝 위치
  duration
  curve            : 이동 곡선 종류 (아래)
  hold             : 시작 후 제자리 버팀 시간 (넉백의 "맞는 순간 정지")
  flags            : 진행 방향 바라보기 여부 등
```

- 이동 곡선 예: 넉백 = `hold` 동안 0 → 짧은 시간에 빠르게 밀리고 감속(ease-out). 돌진 = 가속 → 등속 → 감속.
- 높이(Y)는 곡선에 넣지 않고 지형을 따른다(서버는 지면 탐지, 클라이언트는 보간된 높이 또는 지형 높이).

**서버**
- 동작 시작 시 끝 위치를 스윕으로 확정하고 이벤트를 브로드캐스트한다(AOI 동일).
- 동작 중에는 물리 충격량·AI 이동 대신 곡선으로 위치를 옮긴다. 캐릭터 컨트롤러는 그 위치를 따라가게 한다.
- 다른 이유로 중단되면(사망, 더 강한 넉백, 잡기 성공 등) `MotionEnd { motion_id, end_time, end_pos }`를 보낸다.

**클라이언트**
- 이벤트를 받으면 엔티티의 보간 버퍼에 "모션 구간"으로 등록한다.
- 렌더 시각이 모션 구간 안이면 위치 = 곡선(렌더 시각 − start_time). 그 구간의 위치 스냅샷은 무시(오차 확인용으로만 사용)한다.
- `MotionEnd`가 오면 그 시각 이후는 다시 스냅샷 보간.
- 같은 렌더 시각(서버 시각 − 보간 지연) 기준이라 모션 전환·스냅샷과 순서가 맞는다.

**넉백 값 버그**: 공격 설정의 넉백 값을 `ValidateHit` → 넉백 이벤트로 전달한다. 원래 의도한 값을 쓴다(확정): 평타 5(약 0.36m), 대검 30. ~~지금은 모든 공격이 15(약 3.2m)로 밀린다.~~ **수정 (2026-10-04, 동작 확인)**: `ValidateHit`에 `knockback` 인자를 추가하고 `ExecuteActorAction`이 `config.knockbackValue`를 넘긴다. NPC가 그 값으로 밀린다(평타 약 0.36m, 대검 약 12.9m. 밀리는 거리 = 값²/70). NPC→플레이어 넉백은 이번 범위가 아니라 고정 20 유지.

**1차 범위는 넉백만**(확정). 보스 돌진·잡기 돌진은 스냅샷 보간으로 두고, 필요하면 이후 같은 구조로 옮긴다.

**S4 구현 (2026-10-04, 클라이언트 2개로 동작 확인)**

| 위치 | 내용 |
|---|---|
| `Common/MotionCurve.h` (신규) | `MotionType`, `MotionCurve`(EaseOutQuad = 일정 감속), `Progress(곡선, hold, duration, 경과 초)`. 서버·클라가 같은 함수로 위치 계산 |
| `Packet.h` | `S2C_P_MOTION_START`(1201), `S2C_P_MOTION_END`(1202) |
| 서버 `NPCControllerComponent` | `AddKnockback`(초기 속도 + 감쇄)을 `StartKnockback`(모션)으로 교체. 거리 = v²/(2×35), 벽 스윕으로 줄임, 이동 시간 = v/35, 버팀 0.06초(`kKnockbackHold`). 모션 중 `PhysicsUpdate`·`LightPhysicsUpdate` 모두 수평 속도 = (곡선 위치(서버 시각) − 현재) / dt. 실제 위치가 곡선에서 0.3m 넘게 벗어나면 중단 기록. 리스폰 시 취소 |
| 서버 `Room` | `BroadcastNpcMotionEvents`: 피격 직후 `MOTION_START`, 물리 갱신 뒤 중단된 모션 `MOTION_END`. 그 NPC를 보는 플레이어에게만 |
| 클라 `NPCScript` | 모션 목록 보관. 렌더 시각이 구간 안이면 수평 위치 = 곡선, 높이·회전은 스냅샷 보간. 새 모션이 오면 앞 모션은 그 시작 시각에 끝냄. `MOTION_END`는 종료 시각을 앞당김. 스폰 시 초기화 |

- **사망 시 넉백 수정 (2026-10-05)**: `Room::OnNPCDead`가 사망 즉시 컨트롤러 물리를 꺼서(`SetPhysicsActive(false)`) 서버에서는 모션이 진행되지 않았다. 클라는 `MOTION_START`대로 시체를 날렸다가 모션이 끝나면 서버 위치(제자리)로 돌아왔다(대검으로 죽일 때 발견). 물리가 꺼져도 진행 중인 모션은 끝까지 진행하도록 `PhysicsUpdate`·`LightPhysicsUpdate`의 조기 반환 조건을 바꿨다(AI 이동은 모션 중 원래 무시).
- 곡선 모양이 기존 물리(일정 감속)와 같으므로 이동 거리·시간은 이전과 같고, 앞에 버팀이 붙고 모든 클라이언트가 같은 곡선을 그린다.
- 아직 안 한 것: AOI 진입 시 진행 중인 모션 전달(모션이 1초 이내라 스냅샷 보간으로 충분하다고 보고 보류), 구간 경계에서 섞기(중단 시에만 작은 튐 가능), 플레이어가 맞는 넉백(고정 20, 범위 밖).

### 5.4 히트스톱과 넉백의 관계

- 히트스톱은 **공격자 클라이언트만의 연출**로 유지한다(서버는 모름). 다른 플레이어 화면에서는 보이지 않는다.
- 넉백 곡선의 `hold`가 모든 클라이언트에서 보이는 "맞는 순간의 정지"를 맡는다.
- 공격자 화면에서는 예측 적중 → 히트스톱 → (서버 왕복 + 보간 지연 후) 넉백 이벤트 재생 순서가 된다. 이 간격을 줄이는 방법은 6장 S6에서 다룬다.
- 히트스톱은 이후 오브젝트별 시간 배율(`GameObject`)로 옮긴다(`HitFeel_Plan_KR.md` 3.2). 이때 보간 버퍼는 **서버 시계 기준이라 오브젝트 시간 배율의 영향을 받지 않게** 한다. 히트스톱 중에도 NPC 위치는 서버 시간대로 흘러가고, 멈추는 것은 애니메이션 등 연출뿐이다.

## 6. 작업 순서

| 단계 | 내용 | 검증 |
|---|---|---|
| **S1. 시계 동기화** | `TIME_SYNC` 패킷, 클라이언트 `ServerClock`, 서버·클라이언트 고해상도 시계 통일, ImGui 표시 | RTT·offset이 안정적으로 수렴. 같은 PC에서 offset ≈ 0 |
| **S2. 보간 버퍼 (NPC)** | `SnapshotBuffer`, `NPCScript` 적용, 상태·액션을 서버 시각에 적용 | 걷는 NPC가 끊기거나 튀지 않음. 디버그로 "서버 최신 위치(유령)"와 렌더 위치를 같이 그려 비교 |
| **S3. 보간 버퍼 (다른 플레이어)** | `SC_PACKET_MOVE._server_time`, `OtherPlayerScript` 적용 | 다른 플레이어 이동·정지·공격 시작이 매끄러움 |
| **S4. 넉백 모션 이벤트** | 넉백 값 버그 수정, `MOTION_START/END`, 서버 곡선 이동, 클라이언트 재생 | 평타·대검 넉백이 모든 클라이언트에서 같은 모양(버팀 → 밀림 → 감속)으로 보이고 오버슈트 없음 |
| **S5. 큰 AI 동작 (보류)** | 보스 돌진·잡기 돌진을 모션 이벤트로. 1차 범위에서 제외, S4 이후 필요하면 진행 | 돌진 시작·정지 시점에 미끄러짐·되돌아감 없음 |
| **S6. 조정** | 보간 지연, 넉백 곡선 수치. 필요하면 공격자 화면에서 맞은 NPC만 넉백 예측 재생 검토 | 체감 확인 |

- 각 단계 공통 도구: **인공 지연·흔들림 시뮬레이션**(클라이언트 수신 처리를 일정 ms 지연시키고 무작위로 흔듦). 같은 PC에서도 실제 네트워크 상황을 재현해 확인한다.

## 8. 결정 사항 (2026-10-04)

1. **보간 지연**: 다른 플레이어 30ms, NPC 70ms.
2. **다른 플레이어 전송 주기**: 지금처럼 둔다. 서버 시각만 추가한다.
